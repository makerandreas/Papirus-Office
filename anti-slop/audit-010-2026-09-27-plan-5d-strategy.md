## 4. Technical Blueprint for Plan 5d (Breaks & Defaults)

### 4.1 Step 1: Fake Breaks Removal (Parser Level)

- **Issue:** `OfficeDocumentParser.kt:906-910` and `SvXMLImportContext.kt:91-94, 194-197` intercept soft breaks (`w:lastrenderedpagebreak` and `text:soft-page-break`) and instantiate `OfficeDocumentElement.PageBreak`, appending `\n\n--- Page Break ---\n\n`. These soft breaks were layout hints from prior desktop sessions, not authored breaks.
- **Action:**
  1. In `SvXMLImportContext.kt`: Remove `importFilter.addElement(OfficeDocumentElement.PageBreak)` under `OdfXmlToken.XML_SOFT_PAGE_BREAK`.
  2. In `OfficeDocumentParser.kt`: Remove `w:lastrenderedpagebreak` and `text:soft-page-break` from triggering `OfficeDocumentElement.PageBreak` and appending text markers. Keep them purely as diagnostic or ignored tokens.

### 4.2 Step 2: Authored Breaks In (ODF & DOCX)

- **ODF Implementation:**
  - Parse `fo:break-before="page"` and `fo:break-after="page"` from automatic and common styles in `SvXMLImport.kt`.
  - When encountering a paragraph whose style carries `pageBreakBefore = true`, emit `OfficeDocumentElement.PageBreak` or flag the paragraph accordingly.
- **DOCX Implementation:**
  - Parse `<w:br w:type="page"/>` inside runs (preserve existing logic in `OfficeDocumentParser.kt:964`).
  - Parse `<w:pageBreakBefore/>` in `w:pPr` and set `pageBreakBefore = true` on the paragraph's `ParagraphStyle`.
  - Parse section starts (`<w:sectPr>` with type `nextPage` or default) as page boundary triggers.
  - Record `w:keepNext` and `fo:keep-with-next` in `ParagraphStyle.keepWithNext`.

### 4.3 Step 3: Body Rectangle Computation

- Use `PageStyleSpec`:
  - `bodyTopDp = marginTopDp + headerHeightDp`
  - `bodyBottomDp = heightDp - marginBottomDp - footerHeightDp`
  - `contentWidthDp = widthDp - marginStartDp - marginEndDp`
- Ensures documents with footers (such as all six Collabora ODTs with 1.54 cm footers) and headers paginate within valid printable areas.

### 4.4 Step 4: Metric-Only Style Chain

- **ODF Cascade:** `style:default-style` (family `paragraph`) -> `style:parent-style-name` -> paragraph named style -> direct automatic style properties.
- **DOCX Cascade:** `w:docDefaults` (`pPrDefault`, `rPrDefault`) -> default style (`Normal` with its `pPr`) -> `w:basedOn` hierarchy -> named style -> direct `w:pPr`.
- Extract metric fields into `ParagraphStyle`:
  - `spaceBeforeUnits` (`fo:margin-top`, `w:spacing w:before`)
  - `spaceAfterUnits` (`fo:margin-bottom`, `w:spacing w:after`)
  - `lineHeightFactor` / `lineHeightExactUnits` (`fo:line-height`, `w:spacing w:line`, `w:lineRule`)
  - `firstLineIndentUnits`, `indentStartUnits`, `indentEndUnits` (`fo:text-indent`, `fo:margin-left/right`, `w:ind`)

### 4.5 Step 5: Document Defaults Replace Hard-Coded Constants (F-21)

- Eliminate hard-coded 14 sp default and 24/20/16 sp heading constants in `StyleResolver`.
- Defaults resolve to the document's declared default (Sample-1: 11 pt; Samples 2-6: 12 pt), falling back to 12 pt only if completely unspecified.
- Synchronize font size across toolbar indicator, paginator, and layout renderer.
